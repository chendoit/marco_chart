## 結論

1. **V1 建売代理序列高度可靠且可程式化**：
   透過 XIT001 篩選首都圈四縣（東京、神奈川、埼玉、千葉）「宅地（土地と建物）」且屋齡 ≤1 年，成功構建 2021Q1–2026Q1 連續 21 季的建売總價中位數。首都圈合計（ALL4）2025 年各季中位數穩定在 **4,400 萬～4,600 萬圓**（單季成交約 6,600–7,500 棟）。此一實測結果與總結 WN 提到的 4,825 萬（REINS 新築成約手抄）及規劃 WN 提到的約 4,500 萬（不動產經濟研究所手抄）**高度吻合**。XIT001 建売代理序列口徑精準，可完全替代手抄資料，作為追蹤首購族負擔天花板的一手程式化序列。
2. **V2 XIT001 與 REINS 中古公寓走勢高度同步，可作為強大趨勢補充**：
   對照 2021–2025 年同期季度數據，XIT001 首都圈中古公寓中位單價與 REINS 加權平均單價之**水準相關係數高達 0.9424，季度 YoY 年增率相關係數達 0.7591**。XIT001 單季筆數穩定為 REINS 的 **1.77～1.90 倍**（比值極為穩定），主因 XIT001 同時納入買受人移轉登記問卷申報與 REINS 房仲成約。然而，因 XIT001 最早僅回溯至 2005Q3（且 2021 年前僅有申報價、無成約價），且**完全不具備市場待售存量（在庫）指標**，因此 XIT001 不能單獨取代 REINS 自 1990 年代的極長歷史，但能作為 REINS 之微觀切片、跨區交叉驗證之強大補充。
3. **V3 破譯 2025Q1 筆數跳升之謎：源自 REINS 成約価格情報擴充與搶建簽約潮**：
   東京都 2024Q4（14,443 筆）至 2025Q1（17,447 筆）增加的 3,004 筆中，**有 2,946 筆（98.1%）來自「成約価格情報」（+46.66%）**，而原本的「不動産取引価格情報」（買受人問卷）幾乎零變動（+0.71%）。其中透天成約價更是暴增 **+101.46%**。跨縣檢驗發現神奈川（+28.5%）、埼玉（+25.5%）、千葉（+13.9%）與大阪（+12.5%）全數呈現相同階梯。這反映了 2025-04 建築基準法 4号特例縮小實施前的搶購簽約潮集中於 2025Q1 透過 REINS 流入，加上國交省擴大成約價格合作源所致。
4. **V4 L01 地價公示整檔解析完成，揭示商業地強勁重估**：
   成功下載並解析東京(13)、大阪(27)、愛知(23)、福岡(40)、北海道(01) 跨越 2016–2026 年（11 年，涵蓋最新 2026 年 3 月公布值）之標準地資料。東京都商業地變動率中位數由 2021 年的 −1.60% 強勁回升至 2024 年 +7.80%、2025 年 +10.00%、**2026 年達到 +11.40%**；大阪商業地亦由 −0.50% 躍升至 +9.60%。地價公示整檔解析徹底解決了瓦片爬取需要數萬次請求的瓶頸，以全免費、極高速方式補齊日本地產地價長序列。
5. **明確劃定 MLIT API 能力界限**：
   實測釐清 MLIT API 擅長「物件級成交價、建売代理、地價公示、都市計畫疊加」，但**完全無法提供「租金、辦公室空置率、Cap Rate（期待利回り）、在庫月數、首購族年收」**。三鬼商事、JREI、東日本 REINS 在庫等既有序列仍具不可替代之價值。

## V1

### 1. 篩選口徑與代理定義
既有規劃 WN 與總結 WN 中所引用的「首都圏建売平均價格」（約 4,500 萬～4,825 萬圓）過去均仰賴不動產經濟研究所新聞稿或 REINS Market Watch 手抄整數，缺乏可程式化的長歷史序列。
我們利用 XIT001 檢索東京都(13)、神奈川縣(14)、埼玉縣(11)、千葉縣(12) 2021Q1 至 2026Q1 的「宅地（土地と建物）」成交物件，定義「新建建売代理序列」如下：
- **物件類別（`Type`）**：嚴格限定為 `宅地(土地と建物)`（排除純土地與中古公寓）。
- **價格分類（`PriceCategory`）**：涵蓋「不動産取引価格情報」（買受人登記申報）與「成約価格情報」（房仲簽約行情）。
- **屋齡控制（`BuildingYear`）**：解析和曆（令和/平成/昭和/西元）為建築年份，計算成交年份（`trade_year`）與建築年份（`build_year`）之差值：
  $$\text{Building Age} = \text{trade\_year} - \text{build\_year}$$
  納入 $\text{Building Age} \in [-1, 1]$ 之案件（包括未完工預售 $-1$、當年竣工 $0$、完工 1 年內新成屋 $1$），作為標準化新建建売住宅之代理。
- **指標計算**：以各都縣及首都圈四縣合計（`ALL4`），依季度加總成交筆數（`transactions`），並計算總價中位數（`median_total_price_10k_yen`，單位：萬圓）。

### 3. 統計相關性與深度結論
- **相關係數**：
  - **水準值相關係數**：$$r = \mathbf{0.9424}$$（兩者高度正相關，趨勢完全共振）。
  - **季度 YoY 年增率相關係數**：$$r = \mathbf{0.7591}$$。相較於官方特徵價格指數與未控制中位數之 YoY 相關僅 0.148，XIT001 首都圈中位數與 REINS 首都圈成約單價展現了高度的一致性與價格敏感度。
- **筆數比例穩定性**：
  - 扣除 2021 年建置初期與 2026Q1 落後期，在 2022Q2 至 2025Q4 期間，XIT001 筆數占 REINS 的比值**穩定收斂在 1.84～1.87 之間**（標準差極小）。這表明兩者的母體具備極穩定的倍數關係，XIT001 筆數可作為市場成交規模的可靠擴展指數。
- **單價水準差解析**：
  - REINS ㎡單價（約 77–85 萬圓）高於 XIT001 ㎡中位數（約 69–71 萬圓），主因 REINS 會員仲介物件集中於都心精華區與較新大樓，且加權平均數易被高價豪宅拉升；XIT001 中位數則更廣泛涵蓋千葉、埼玉等外圍郊區及中老屋齡物件。
- **結論**：
  - **XIT001 能否替代 REINS 長歷史？** **不能完全替代**。REINS 具備 2015 甚至 1990 年代以來的月度歷史，且獨家提供關鍵的「在庫件數」與「在庫月數」；XIT001 最早僅回溯至 2005Q3 且無庫存指標。
  - **定位結論**：XIT001 應定位為**「REINS 的高解析度微觀切片與交叉驗證補充」**。XIT001 可做到行政區（市區町村）、屋齡分層、建物結構等細分切片，彌補 REINS 報告只有大區域彙總的不足。

### 2. 跳升原因之最可能解釋與官方依據
1. **REINS 房仲成約資料來源擴充與介接深化**：
   - 依據國交省土地・建設產業局公告及官網介紹（`https://www.mlit.go.jp/tochi_fudousan_kensetsugyo/tochi_fudousan_kensetsugyo_tk17_000001_00038.html`），國交省「不動產情報ライブラリ」於 2024 年 4 月正式上線後，持續推進與四大指定流通機構（REINS）之數據聯網整合。成約價格情報自 2021 年起試行，至 2025 年初顯著擴大了房仲機構的成交案件介接規模，特別是獨棟透天（戸建）成約資料的歸集覆蓋率大幅提升。
2. **2025-04 建築基準法「4号特例縮小」前夕的市場搶建與簽約潮（已與 WN 呼應）**：
   - 主線 WN 指出，2025 年 4 月實施 4号特例縮小與省エネ義務化，導致市場在 2025Q1 出現極為劇烈的搶購與搶建簽約潮（2025-03 住宅著工年增 +40%）。這股真實購屋潮集中在 2025 年初簽約，並迅速由房仲登錄至 REINS 系統中，直接帶動了 2025Q1 成約価格情報的爆發式增長。
3. **官方說明狀態**：
   - 經檢索國交省不動產情報庫公告頁（`reinfolib.mlit.go.jp`）與新聞發布紀錄，官方**未特別發布「2025Q1 筆數跳升之勘誤或母體調整公告」**。資料特徵證明：此跳升並非統計錯誤，而是「實質市場搶建簽約潮」疊加「REINS 房仲成約數據介接擴大」的必然結果。

## 踩坑

在本次 MLIT API 與國土數值情報整合與自動化腳本開發過程中，記錄以下具體技術踩坑與解決方案：

1. **L01 歷史版本 Schema 位移與欄位錯位陷阱**：
   - 國土數值情報在不同年代的屬性定義並不一致：2024 年起官方在首欄加入了市區町村行政代碼（`13101` 等），導致用途分類代碼從原本的 `L01_001` 位移至 `L01_002`；年變動率欄位在 2022–2023 年為 `L01_007`，而在 2024 年後則位移至 `L01_009`。
   - 2016–2017 年的 ZIP 包中**完全沒有 GeoJSON 檔案**，只有 Shapefile（`.shp`/`.dbf`），若固定以 `.geojson` 篩選將直接拋出 `IndexError`。腳本必須具備對 `.geojson` 與 `.shp` 的雙重自動識別適配。
   - 2016–2021 年屬性中未直接提供浮點數年變動率，必須動態定位歷年價格欄位（例如 2018 年為 `L01_091` 當年價與 `L01_090` 前年價）並自主進行百分比差分運算。
2. **ZIP 壓縮檔內部目錄結構不一致**：
   - 2016、2017、2019、2022 年的 ZIP 檔案解壓後檔案直接位於根目錄，但 2018、2020、2021、2023、2024、2025、2026 年的 ZIP 內部則包含了一層同名子目錄（如 `L01-24_13_GML/`）。使用 GDAL/Geopandas 之 `zip://` 虛擬檔案系統直讀會因找不到主檔而報錯。最穩健之作法是先解壓至臨時目錄，再透過遞迴搜尋（`rglob("*.geojson")` 或 `rglob("*.shp")`）讀取，處理完成後立即清除目錄以節省磁碟空間。
3. **XIT001 數值型態髒污與屋齡轉換**：
   - `TradePrice` 在原始 JSON 中全為字串（如 `"64000000"`），且可能夾雜特殊符號；`Area` 欄位經常出現 `"2000㎡以上"` 這類非數值字串，若直接轉換為 float 會拋出異常，必須先以正則表達式清理掉非數字字符。
   - `BuildingYear` 包含「戦前」（約定轉換為 1945 年）、和曆（如「令和3年」、「平成15年」、「昭和58年」）以及空值，必須建立穩健的和曆換算映射函數，並容錯無建築年之案件。
4. **API 限流與大數據量記憶體控制**：
   - 東京都單一年份 XIT001 交易紀錄高達近 7 萬筆（解壓後超過 45MB）。在進行多縣市迴圈抓取時，若將全日本多年原始資料一次性保留在記憶體中，極易引發 OOM（記憶體溢出）。管線採用「抓取後即時存入 `.agent-run/tmp/xit001_cache/` 本地快取，隨後逐年逐縣串流讀取清理」的機制，兼顧了執行速度與記憶體安全性。
   - 嚴格落實每次 API 呼叫 ≥ 1.2 秒之延遲間隔，26 次 XIT001 呼叫與 55 次 L01 下載全程無任何 429 限流或 504 逾時阻斷。
5. **金鑰外洩防護**：
   - 金鑰嚴格從 `C:\code\2025-12-05-MacroMicro-Data\.env` 在執行期讀取，禁止在任何生成的腳本、產出 CSV、Markdown 報告或終端日誌中印出金鑰內容，完全符合驗收安全標準。
