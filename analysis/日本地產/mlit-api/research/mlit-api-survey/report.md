# 日本國土交通省「不動產資訊庫 API」（reinfolib）深度調研與實測報告

- 調研日期：2026-10-15
- 調研對象：日本國土交通省（MLIT）不動産情報ライブラリ（Reinfolib）公開 API
- 官方手冊手冊：https://www.reinfolib.mlit.go.jp/help/apiManual/
- 官方利用規約：https://www.reinfolib.mlit.go.jp/help/termsOfUse/
- 基準環境：Python 3.12+ / requests / pandas，認證標頭 `Ocp-Apim-Subscription-Key`

---

## 結論

1. **API 體系架構完整且層級分明（共 35 支公開 API）**：
   官方手冊列出 35 支公開 API，涵蓋**不動產價格情報（成交價與簽約價 XIT001、鑑定評價書 XCT001、價格點位 XPT001、公示地價點位 XPT002）**、**基礎行政區代碼（XIT002）**、**都市計畫 GIS 分區（XKT001~003、014、023、024、030）**、**周邊公共設施與學區（XKT004~011、017~019）**、**微觀人口與軌道交通（XKT013 250m網格推計人口、XKT015 車站年度乘降客數、XKT031 人口集中地區）**，以及**全方位災害風險圖層（XKT016、020~022、025~029、XGT001、XST001）**。
2. **微觀真實交易數據覆蓋長達 20 年（2005Q3 至今），單次回傳規模龐大**：
   核心端點 `XIT001` 提供日本全國不動產真實交易價格（不動産取引価格情報，2005 年第 3 季起）與房仲簽約價（成約価格情報，2021 年第 1 季起）。實測單次以「年＋都道府縣」查詢（如 2024 年東京都），可一次性回傳 57,960 筆物件層級明細，無須分頁查詢，資料吞吐能力極強。
3. **成功實測 12 支代表性端點（全數 HTTP 200 通過）**：
   涵蓋成交價明細（XIT001）、行政代碼（XIT002）、鑑定評價書（XCT001）、成交點位（XPT001）、地價公示（XPT002）、都市計畫分區（XKT001、XKT002）、將來人口網格（XKT013）、車站客流（XKT015）、洪水淹水風險（XKT026）、避難場所（XGT001）及災害歷史（XST001），全數回傳有效資料與幾何結構。
4. **具備構建高頻地產中位數指數的完備能力**：
   我們實際抓取東京都 2021Q1 至 2026Q1 共 309,984 筆真實成交資料，成功建構季度中位數單價與成交量指標。數據清晰揭示東京 23 區二手公寓（中古マンション）單價由 2021Q1 的每平米 86.6 萬日圓（每坪 286.5 萬日圓）飆升至 2025Q4 的每平米 111.4 萬日圓（每坪 368.4 萬日圓），累計漲幅達 28.6%，具備極高商業與總經研究價值。
5. **高度友善的公共數據授權（可二次加工與商用）**：
   官方全面適用「公共データ利用規約（第1.0版）」（PDL 1.0，相容 CC BY 4.0），明確允許商業利用與二次衍生創作；只需依規約標明出處與免責聲明即可合法整合進 MacroMicro 平台圖表與報告中。
6. **雙重架構特性：屬性資料（REST JSON）與空間圖層（XYZ Vector Tile）並存**：
   XIT001/XIT002/XCT001 為傳統屬性查詢 REST API，便於大量匯入資料庫；而所有 XKT/XPT/XGT 圖層均採 WebGIS 標準之 XYZ 瓦片切片（GeoJSON/PBF），微觀解析度極高（可達 Zoom 15），但若欲進行全國級空間聚合需編寫瓦片爬取與空間合併管線。
7. **無可替代的獨特價值在於「物件級微觀切片」與「空間跨界對齊」**：
   相較於 e-Stat 或 REIC 僅提供巨觀匯總指數，reinfolib 能自由針對「特定行政區 × 特定用途 × 特定屋齡 × 軌道人流 × 淹水風險」進行精確切片加權，是打造差異化地產總經深度指標的核心資料庫。

## 踩坑

在實際介接與解析 Reinfolib API 過程中，我們歸納出以下五大技術注意事項與具體應對方案：

1. **認證機制與金鑰傳遞（Authentication）**：
   - **常見陷阱**：許多開發者習慣將金鑰放在 URL Query String（如 `?api_key=...`）或 Authorization Header（`Bearer ...`），但在 Reinfolib 會直接被 Azure API Management 網關拒絕並拋出 `401 Access Denied`。
   - **正確作法**：必須使用特定的 HTTP Header 名稱：`Ocp-Apim-Subscription-Key: <TOKEN>`。此外，官方強烈禁止在前端瀏覽器直接呼叫（因無 CORS 標頭且會洩漏金鑰），所有呼叫均需經由後端代理。
2. **編碼與 Gzip 傳輸解壓縮（Encoding & Compression）**：
   - **常見陷阱**：屬性 API（特別是 `XIT001` 與 `XCT001`）的回傳資料預設強制以 Gzip 壓縮傳輸（即使未發送 Accept-Encoding: gzip），終端使用原生 `curl` 時若未加上 `--compressed`，輸出將是一堆二進位亂碼；在 PowerShell 終端直接重定向 `>` 還會因為 Windows 預設 CodePage（cp950 / cp932）造成日文字符毀損。
   - **正確作法**：Python `requests` 與 `curl_cffi` 會自動根據 Response Header 處理 Gzip 串流解壓。另外在寫入本機檔案時，一律強制指定 `encoding="utf-8"` 或 `utf-8-sig`，嚴格避開 Windows 命令列字碼陷阱。
3. **Tile 格式與坐標邊界限制（Tile XYZ Constraints）**：
   - **常見陷阱**：XKT / XPT / XGT 系列均採 XYZ 瓦片（Slippy Map Tiles）切片，且對縮放層級（Zoom Level, `z`）有極為嚴格的硬性檢驗。例如地價公示點（XPT002）僅支援 `z=13~15`，若傳入 `z=11` 或 `z=12` 會立即回傳 `400 Bad Request`（縮放層級超出允許範圍）。
   - **正確作法**：呼叫前必須參照各端點的手冊規格嚴格限制 Zoom 範圍。對於多邊形圖層（如用途地域 XKT002），同一地塊若跨越多個 Tile，會在不同 Tile 內被裁切成多個 Geometry，如需進行全區空間運算，必須在本地使用 Shapely / GeoPandas 進行 `unary_union` 幾何融合。
4. **欄位數值格式與單位清洗（Units & Formatting Trap）**：
   - **常見陷阱**：
     - `TradePrice`（成交總價）為日圓整數，但型態為 String（例如 `"64000000"`），且可能包含空白。
     - `Area`（面積）多數為數值字串，但遇大面積地塊時會出現 `"2000㎡以上"` 這種帶文字後綴的值，若直接 `float()` 會噴拋例外。
     - `UnitPrice`（每平米單價）在透天住宅（土地與建物）時經常為 `null` 或空字串，因為官方交易通常僅申報總額；若需計算透天住宅單價，必須手動透過 `TradePrice / Area` 自行派生。
     - 坪單價換算：日本法定 1 坪等於 $3.30578$ 平方公尺（400/121 ㎡），計算坪單價時需將每平米單價乘以 $3.30578$。
5. **限流策略與查無資料回應碼差異（Rate Limiting & 404 Behavior）**：
   - **常見陷阱**：一般 RESTful API 在無資料時通常回傳空陣列 `[]`，但 Reinfolib 的**非 Tile API（XIT001、XIT002、XCT001）在無符合資料時會直接回傳 HTTP 404**！若程式碼只判斷 `resp.status_code == 200`，遇到合法但無資料的年份/區域會誤判為端點失效。相反地，Tile 類 API 無資料時卻回傳 `HTTP 200 + features: []`。
   - **限流處理**：官方 Q&A 表明「同一金鑰在基準期間內有過多請求會觸發限流，無固定上限」，實測請求間隔保持在 1.0 ~ 1.5 秒以上運作非常穩定，未發生過 `429 Too Many Requests`。

## 利用規約重點

日本國土交通省對於「不動產情報庫（Reinfolib）」的授權條款非常開明，其核心法律與規範架構如下：

1. **著作權歸屬與 PDL 1.0 授權**：
   - 網站與 API 內容之著作權特記以外均歸屬**國土交通省**。
   - 適用「**公共データ利用規約（第1.0版）**」（PDL1.0），其本質與政府資料開放及 **Creative Commons Attribution 4.0 International（CC BY 4.0）** 精神相容。
2. **商業利用與二次加工授權**：
   - **明確允許二次加工、分析、展示與商業利用（商用利用可能）**。API 利用者可無償將取得的資料整合至商業性產品、分析平台（如 MacroMicro）、報表或付費訂閱服務中。
3. **出處標示規範（クレジット表示）**：
   - **基本引用格式**：
     `出典：国土交通省　不動産情報ライブラリ（https://www.reinfolib.mlit.go.jp/）`
   - **二次加工/加值服務引用格式**：
     若對資料進行加工、清洗或計算指標，必須加註：
     `「不動産取引価格情報」（国土交通省）をもとに○○（例如 MacroMicro / 財經M平方）作成`
