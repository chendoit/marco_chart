# 港股每日成交額（全市場）抓取報告

## 結論

- **未達成主目標**：目前找不到可程式化取得的 HKEX 主板＋GEM 全市場每日成交額官方數字。HKEX 每日行情頁（`dayquot/d<yymmdd>e.htm`）在本環境對所有測試日期皆回 404，HKEX 其他統計端點多數 404 或 403。
- **已交付代理序列**：`fetch.py` 以東方財富 `100.HSI`（恒生指數）的成交額欄位（`f6`）產出 `market_turnover.csv`，共 2166 個交易日，2018-01-02 至 2026-10-22。此序列**很可能是恒指成分股成交額，不是全市場成交額**，且尚未與 HKEX 官方數字核對，不能直接當全市場序列使用。
- 全歷史回補只需一次 API 請求（約 1 秒），不需分批。

## 涵蓋範圍與是否全市場

- **是否全市場：否（未證實）。** 東方財富指數成交額通常是成分股成交額加總，預期低於全市場（主板＋GEM）總額。本次無官方數字可核對，因此無法判定差距。
- 因此 CSV 的 `source` 欄標示為 `eastmoney_HSI_f6_constituent_proxy`，請勿當作全市場數字使用。
- 南向／港股通成交：未處理（非主目標）。

## 起始日

- 資料起點：2018-01-02（東方財富提供的最早日線）。

## 可行性

- 抓取：可行，全歷史一次請求，約 1 秒。
- 全歷史回補預估時間：< 1 分鐘（單次請求＋寫檔）。
- 若要改為全市場數字，需要 HKEX 付費資料或另覓可免費取得的官方每日總額來源。

## 踩坑

1. **HKEX 每日行情 URL 失效**：`dayquot/d<yymmdd>e.htm` 對所有測試日期皆 404，無法用舊法逐日抓取。
2. **當日盤中數字不完整**：東方財富會回傳當天未完成的資料（例如 2026-10-23 僅 25.9 十億，遠低於前一日 2560 億），因此 `fetch.py` 會排除 `date >= 今日` 的列。若在收盤前執行，今日資料也不會寫入。
3. **增量時要注意已存的盤中列**：`fetch.py` 讀取既有 CSV 後會再次過濾 `date >= 今日`，避免殘留不完整資料。
4. **快取**：原始 JSON 存於 `cache/hsi_<start>_<end>.json`。若要強制重抓，刪除對應快取檔即可；日更時 `end` 固定為 `20500101`，所以快取檔名會隨 `--start` 變化。

## 建議日更抓法

- 每日收盤後（HK 16:30 之後）執行 `fetch.py`，以東方財富最新日線補上當日數字。
- 增量：`fetch.py --start <最後一個已完成交易日>`；程式會保留既有列並覆寫該起日之後的列。
- 若要使用全市場數字，需另接官方來源；目前代理序列只適合做趨勢參考，並須在下游標明來源。
